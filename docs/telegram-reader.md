# Telegram Reader POC

Реализованы `login`, `groups` и `watch` на Telethon 1.x. Это пользовательский
клиент отдельного аккаунта, не бот. Case, matching, доменная SQLite, Writer,
Outbox, LLM и Langfuse пока не подключены.

## Подготовка

Нужны Python 3.13, uv, авторизованный Proton Pass CLI (проверенный интерфейс:
2.7.1) и доступ к vault `aenea`. В item `telegram` пользователь заранее создаёт
поля `api_id`, `api_hash`, `phone`. Телефон — в международном формате с `+`;
это номер отдельного аккаунта для POC. Не отправляйте hash, код входа или пароль
2FA в чат и не вставляйте их в команды.

Из корня репозитория:

```sh
uv sync --locked --all-packages
cp configs/telegram/dev.login.env.example .env.telegram-login
cp configs/telegram/dev.reader.env.example .env.telegram-reader
```

Оба файла содержат только ссылки и `AENEA_ENV=dev`, игнорируются Git. Они
преднамеренно отделены от полного `.env`: для Telegram POC не нужны credentials
OpenAI и Langfuse. Не выполняйте `source` и не генерируйте plaintext dotenv.

## Первый вход

Выполните в интерактивном локальном терминале:

```sh
pass-cli run --env-file .env.telegram-login -- \
  uv run --locked --package aenea-telegram-agent aenea-telegram login < /dev/null
```

Код из Telegram и, при необходимости, пароль 2FA запрашиваются через управляющий
терминал `/dev/tty` (macOS/Linux). Вместо символов показываются звёздочки;
Enter отправляет ввод, Backspace удаляет символ, Ctrl+U очищает ввод. Поддерживается
вставка из буфера, в том числе bracketed paste. Реальные символы не печатаются.
Без управляющего терминала или возможности отключить echo CLI отказывается
выполнять вход. При завершении, EOF, таймауте и отмене настройки терминала
восстанавливаются; остаток ввода после Enter сбрасывается.

`< /dev/null` отключает перенаправление stdin самим Proton CLI: ввод читает
только приложение через `/dev/tty`, без конкурирующего читателя. Стандартное
маскирование `pass-cli run` остаётся включённым; `--no-masking` не нужен.
Ввод не блокирует сетевой цикл Telethon. После Enter отображается статус
проверки кода/2FA, затем сохранения сессии. Для подключения и каждого Telegram
запроса авторизации установлен таймаут 30 секунд, для ввода — пять минут.
Неверный код, ошибка авторизации или FloodWait останавливают команду; повторных
попыток входа и регистрации аккаунта автоматически нет.

Перед сетевым входом CLI проверяет отсутствие активного item `telegram-session`
в vault `aenea`. После авторизации создаёт этот item с hidden-полем `secret`
через `pass-cli item create custom --vault-name aenea --from-template -`.
Сессия передаётся JSON через stdin; вывод Proton CLI захватывается и не печатается.
Никакого локального `.session`/SQLite-файла или вывода StringSession нет.
Ссылка сохранённой сессии — `pass://aenea/telegram-session/secret`.

Не запускайте несколько `login` одновременно: Proton CLI не предоставляет
атомарный create-if-absent по имени. Имя проверяется перед входом и перед записью,
но параллельное создание всё равно может породить неоднозначные ссылки.

Если вход или сохранение прерваны ошибкой, CLI пытается отозвать новую сессию
через Telegram `log_out` с таймаутом 10 секунд. Если отзыв также не подтверждён, завершите этот сеанс
в официальном Telegram: **Настройки → Устройства**. При таймауте создания сначала
проверьте наличие item в Proton Pass: сервер мог сохранить его до потери ответа.
Не повторяйте создание вслепую; сохранённая при таком сбое сессия могла быть отозвана.

## Группы

```sh
pass-cli run --env-file .env.telegram-reader -- \
  uv run --locked --package aenea-telegram-agent aenea-telegram groups
```

Вывод — JSON Lines с `chat_id` и `title` только для групп, включая супергруппы.
Личные диалоги и вещательные каналы не выводятся. Список диалогов Telegram
технически содержит metadata и последних сообщений других диалогов; клиент
не запрашивает их историю, не выводит и не сохраняет их содержимое.
Во время `groups` получение updates отключено. На большом аккаунте перечисление
может потребовать нескольких запросов; FloodWait соблюдается остановкой и
указанием срока ожидания.

## Чтение выбранной группы

Подставьте точный `chat_id` из `groups`:

```sh
pass-cli run --env-file .env.telegram-reader -- \
  uv run --locked --package aenea-telegram-agent aenea-telegram watch --chat-id=-1001234567890
```

Аргумент — явный выбор одной группы на время запуска. CLI проверяет, что это
группа, уже доступная аккаунту, затем выводит запись `watching`. Новые сообщения
выводятся JSON Lines: группа, ID сообщения и автора, время и текст. Медиа не
скачиваются; подпись, если есть, отображается как текст. Изменения и удаления
сообщений пока не обрабатываются. Unicode экранируется JSON, в том числе
терминальные управляющие символы. Для остановки — `Ctrl+C` (exit code 130).

Чтение сессии выполняет исключительно native `pass-cli run`. В `groups`/`watch`
нет автоматического входа: отсутствующая, некорректная или отозванная сессия —
ошибка. Процесс держит StringSession и entity cache в памяти, при завершении
не выгружает их на диск. Секреты, тексты RPC-ошибок и диагностические логи
Telethon не публикуются. Вывод `watch` намеренно содержит текст выбранной группы;
не перенаправляйте его в общий лог или hosted-телеметрию.

## Ограничения и восстановление

- Читаются только новые сообщения во время подключения. StringSession хранит
  авторизацию, но не checkpoints обработки. Нет гарантии восстановления пропусков
  при перезапуске или разрыве соединения. Это live POC, не надёжный Inbox.
- Read-only ограничивает действия приложения, а не полномочия авторизационного
  ключа Telegram. В коде Reader нет отправки сообщений, реакций, вступления,
  изменения read acknowledgements или ghost mode. Протокольные статусы Telethon
  не подменяются.
- StringSession даёт доступ к аккаунту. Её хранилище — только Proton Pass vault
  `aenea`; локальные reference-файлы содержат URI, а процесс получает значение
  через окружение. Не включайте debug-вывод, `env` или дампы процесса.
- Установленный CLI не умеет безопасно обновить поле через stdin. Обычный
  повторный запуск использует тот же ключ и не требует записи. CLI проверяет
  сериализованную сессию после подключения, при завершении и раз в секунду во
  время `watch`. Если обнаружено изменение (например, DC), CLI
  сообщает об этом и не обновляет secret через argv. Это не автоматическая
  миграция/ротация сессии.
- Если сессия отозвана, повреждена или требует восстановления: остановите все
  Reader-процессы, вручную завершите соответствующий сеанс в Telegram, затем
  самостоятельно переименуйте или переместите в корзину старый item в Proton
  Pass и выполните `login` снова. CLI не удаляет и не ротирует credentials.
  Сохраняйте однозначность активного имени `telegram-session`.
- Прямые IP, Test Configuration и RSA public keys из my.telegram.org не нужны
  для обычного production-подключения. Тестовая сеть этим CLI не поддерживается.

Offline-проверки не подключаются к Telegram или Proton Pass:

```sh
uv run --locked --package aenea-telegram-agent python -m unittest discover -s tests -v
```

Live-проверка: выполнить `login`, дважды запустить `groups` (без нового кода),
затем `watch` для выбранной тестовой группы и отправить в неё сообщение вручную
из официального клиента. В терминале должна появиться запись только выбранной
группы. Затем проверить, что сообщение другой группы не выводится. Это ручная
проверка; прохождение offline-тестов само по себе её не подтверждает.
