# Aenea: локальный интерфейс для Windows и macOS

status: idea to review

Дата: 24 ноября 2026 года. Идея на потом, не согласованный дизайн и не задача
текущего MVP. Основание — [архитектура](../../architecture.md) и
[Telegram Reader POC](../../telegram-reader.md).

## Идея

Предусмотреть локальное оконное приложение как общий интерфейс Aenea для Windows
и macOS, без обязательного веб-сервера, SaaS или размещения интерфейса в облаке.
Локальный интерфейс не отменяет сетевые подключения к Telegram и Proton Pass.

Первый сценарий — визард подключения Telegram и экран настроек: пройти вход
с кодом/2FA в окнах, сохранить сессию в защищённое хранилище (сейчас Proton Pass
vault `aenea`), увидеть доступные группы и явно выбрать их чекбоксами вместо
ручного переноса `chat_id`. Выбор сохраняется; пользователь видит состояние
чтения и может запустить или остановить его. По умолчанию группы не выбраны,
личные диалоги исключены; выбор группы не разрешает отправку или LLM-обработку.

Сейчас `login` использует Unix-терминал, сохраняет сессию в Proton Pass,
а `watch --chat-id` читает одну явно выбранную группу на время запуска.
Будущий GUI должен использовать общую прикладную логику без зависимости от
`/dev/tty`; секреты не становятся обычными настройками или локальными файлами.

## Что проверить перед принятием

Выбрать GUI-технологию и способ упаковки для обеих ОС; проверить работу с
Proton Pass без терминала и безопасный ввод кода/2FA. Отдельно определить
жизненный цикл чтения при закрытии окна и поддержку нескольких выбранных групп.
GUI не должен стать второй реализацией Reader или поводом заранее строить
отдельный сервер. Остальные экраны системы определить по мере появления
сценариев; сейчас их не проектировать.
