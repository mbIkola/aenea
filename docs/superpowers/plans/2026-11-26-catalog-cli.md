# Подключение Read CLI каталога к RaidSL

Продолжение PR3 после получения READ-API.md, read-contract.schema.json и
agent_sdk_tools.py внешнего champion-catalog. Другой репозиторий только читаем.

1. Сохранить fixture-режим и выделить маленькую фабрику per-run tools/evidence.
2. Подключить create_catalog_tools из явно выбранного локального файла. Передать
   фиксированные пути CLI, каталога и metadata; модель их не выбирает.
3. Проверять JSON envelope и публичную схему v1, сохранять business errors как
   результаты tools. Успех каждого tool должен соответствовать его части схемы.
4. Наблюдать только validated builds. Draft ready содержит выбранный build,
   определения талантов, provenance и warnings. Портрет не является картинкой
   талантов: без renderer asset_ref остаётся null.
5. Писать тесты до реализации: настоящий SDK loop на fake Model; структурированные
   ошибки, неверная схема, unvalidated, потерянные definitions и evidence изоляция.
   CI использует самодостаточную fixture CLI; внешний checkout не обязателен.
6. Проверить настоящую фабрику SDK и offline CLI на локальном каталоге. При live
   smoke передавать только ручной игровой запрос и общедоступные данные каталога,
   не читать Telegram Inbox. Обновить русские docs и текущий PR3.

Результат: выполнено. 117 offline-тестов, Ruff check/format, сборка четырёх
пакетов и наличие schema в wheel проверены. Реальная фабрика/CLI проверены
без модели; Packet smoke подтвердил уточнение неоднозначной роли и ready
для Ronda pve-1 с 15 определениями талантов. Замечание review по санитизации
ошибок импорта фабрики исправлено и покрыто тестом.
