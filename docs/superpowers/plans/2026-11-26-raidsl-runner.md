# PR3: отдельный RaidSL и Agents SDK Runner

## Согласованный объём

Отдельный пакет `aenea-raidsl`, локальный асинхронный Agents SDK Runner,
явное переключение OpenAI/Packet через dev-конфигурацию и два tools на тестовых
данных. Внешний каталог и алгоритм получения талантов ещё готовятся: фиксируется
внутренний интерфейс адаптеров, а не формат внешнего JSON. Aliases, переводы
и art-ссылки необязательны. LLM не подключается автоматически к Telegram Reader.

## Решения

- Dummy RaidSL переносится из общего packages/agents в packages/raidsl;
  registry Reader сохраняет прежнее поведение ignore.
- AgentHub/Router остаются независимыми от Agents SDK. У нового Runner отдельный
  ручной demo-entrypoint; нет второго оркестратора и фонового сетевого вызова из Reader.
- OpenAI использует Responses, Packet — OpenAIChatCompletionsModel. Провайдер,
  модель и credentials выбираются явно, без fallback между провайдерами.
- Секреты получает native pass-cli run из vault aenea. Reference-профили содержат
  только ссылки; пользовательские .env и save-openai-api-key.py не меняются.
- Встроенный SDK trace-export выключен; контекст tools и конфигурация с ключом
  не должны попадать в repr, сообщения ошибок или диагностические логи.
- Два tools: search_characters и get_masteries. Второй работает только с ID,
  фактически возвращённым поиском. Итог ready принимается лишь для результата,
  полученного tool в текущем запуске. Файловые пути модель не выбирает.
- Число шагов, время запуска и вывод модели ограничены. Итог проверяется локально,
  без зависимости от vendor-specific strict structured output.
- Результат — локальный draft, не выполненная отправка. Case/Outbox и автоматическая
  обработка реальных Telegram-сообщений не входят в PR3.

## Порядок реализации и проверки

1. Подготовить пакет, зафиксировать актуальную версию SDK в lockfile.
2. Написать и увидеть падающие тесты конфигурации, адаптеров, tools и обработки
   поддельного/неоднозначного результата до реализации поведения.
3. Реализовать пакет с fixture-каталогом, fixture-талантами, tools и Runner.
4. Проверить настоящий Agents SDK loop с fake Model: tool calls → outputs → final.
   Добавить HTTP mock-проверки обоих протоколов без ключей и сетевых запросов.
5. Перенести dummy, сохранив backward compatibility CLI Reader и его тестов.
6. Написать русскую документацию, reference-профили dev и миграционный контракт
   будущего каталога; выполнить весь offline-набор, Ruff, build и code review.
7. Если Proton-доступ доступен, проверить ограниченный live demo только на
   синтетическом вопросе/fixture-данных; результаты и ограничения указать явно.

## Результат

Шаги выполнены. 110 offline-тестов проходят, проектные Python-файлы проходят
Ruff, четыре пакета собраны. Независимое review не нашло обязательных исправлений.
Оба live-demo завершились с ready/fixture=true за три model requests каждый.
Реальный каталог, алгоритм талантов и автоматическая обработка Telegram отложены
в соответствии с согласованными границами PR3.
