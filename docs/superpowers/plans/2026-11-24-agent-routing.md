# План registry и dummy RaidSL

Цель: реализовать AgentHub → Router → Agent → Action → Writer без LLM и отправки в Telegram.
Пользователь одобрил общий механизм регистрации и маршрутизации и минимальный RaidSL.

## Границы

- `packages/agents`: независимые контракты, registry, Router по паспортам, dispatcher,
  IgnoreWriter и dummy RaidSL. Router не вызывает агентов для проверки интереса.
- RaidSL объявляет триггер-фразы; возвращает карточку и IgnoreAction. Персонажи,
  таланты, изображения и HITL остаются за пределами этого среза.
- SQLite сохраняет терминальный результат обработки сообщения. Пока нет внешних
  эффектов, отдельный Outbox и полноценный Case не вводятся.
- Сохранённая строка messages без результата является незавершённой работой.
  Это позволяет восстановить обработку без отдельной таблицы inbox_events на этом
  узком срезе. Будущие ожидающие кейсы и отправки потребуют отдельного дизайна.
- `watch --route` включает обработку явно; `route --db --source-account-id --chat-id`
  позволяет обработать ранее сохранённые сообщения offline. `agents` показывает registry.
- Текущая ветка codex/telegram-reader-poc уже содержит подготовленный Inbox;
  продолжаем в ней, без смены checkout и authenticated-операций.
